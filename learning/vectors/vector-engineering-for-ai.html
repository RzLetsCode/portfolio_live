1. Manhattan vs. Euclidean Distance

Euclidean Distance ($L_2$)

Measures straight-line "as the crow flies" distance. Ideal when movement across axes is smooth and continuous.

$$d_{L2}(\mathbf{x}, \mathbf{p}) = \sqrt{(x_1 - p_1)^2 + (x_2 - p_2)^2}$$

Primary Use Cases: Low-dimensional spatial tracking, standard clustering (K-Means), and physical coordinate mapping.

Manhattan Distance ($L_1$)

Measures "city grid / taxi" distance along axis-parallel paths: $|\Delta x| + |\Delta y|$.

$$d_{L1}(\mathbf{x}, \mathbf{p}) = |x_1 - p_1| + |x_2 - p_2|$$

Primary Use Cases: High-dimensional feature spaces, independent feature dimensions (e.g., Age vs. Income), and outlier-robust modeling.

2. K-Nearest Neighbors: L1 vs L2 Visualized

Why Use Manhattan Distance in AI?

  • As the Crow Flies ($L_2$): Direct straight-line diagonal path.
  • City Grid / Taxi ($L_1$): Restricts movement along city blocks ($\Delta x + \Delta y$).
  • High-D Robustness: In high dimensions, $L_1$ prevents distance collapse.
Classification Decision: Patient $X(3,5)$ is closer to $P_2(4,6)$ under both metrics ($L_2 = 1.41$, $L_1 = 2$) than $P_1(1,2)$ ($L_2 = 3.61$, $L_1 = 5$), categorizing $X$ as High-Risk.

3. Decoding Word Embeddings: $[f_1, f_2, f_3]$

Semantic Trait Dimensions

In Large Language Models, continuous vectors store explicit semantic scores:

  • $f_1$ (Masculinity): $1.0 =$ Male, $0.0 =$ Neutral / Female.
  • $f_2$ (Royalty / Power): $1.0 =$ Monarch, $0.0 =$ Commoner.
  • $f_3$ (Femininity): $1.0 =$ Female, $0.0 =$ Neutral / Male.

Semantic Vector Arithmetic

Formula: $\text{King} - \text{Man} + \text{Woman} = \text{Queen}$

King: [0.9, 0.8, 0.1]

- Man: [0.8, 0.1, 0.1] &implies; [0.1, 0.7, 0.0]

+ Woman: [0.1, 0.1, 0.9] &implies; [0.2, 0.8, 0.9]

Result: [0.2, 0.8, 0.9]

Subtracting "Man" strips masculinity traits, while adding "Woman" injects femininity, synthesizing the exact embedding for Queen.

4. Semantic Vector Trajectory in Action

Trajectory Analysis

  1. Base Vector: We begin at the coordinate for King $[0.9, 0.8, 0.1]$.
  2. Subtract Concept: Subtracting Man removes masculinity, shifting the vector along the horizontal axis to $[0.1, 0.7, 0.0]$.
  3. Add Concept: Adding Woman injects femininity, driving the trajectory upward along the vertical axis to $[0.2, 0.8, 0.9]$.
LLM Takeaway: High-dimensional embeddings capture real-world analogies purely through spatial translations and geometric operations.

5. Vector Search & RAG: Query Projection

Isolating Intent via Projection

When searching a Vector DB (Pinecone, Weaviate):

  • Query Vector $\mathbf{q} = (3, 4)$: User intent containing both Technical ($3$) and Gossip ($4$) traits.
  • Document Axis $\mathbf{d} = (1, 0)$: Document chunk containing Pure Technical Content.
$$\text{Scalar Projection} = \frac{\mathbf{q} \cdot \mathbf{d}}{\|\mathbf{d}\|} = \frac{(3)(1) + (4)(0)}{1} = 3.0$$

Vector Projection $\mathbf{p} = (3, 0)$

The perpendicular drop isolates the exact overlap magnitude ($3.0$) along the technical document line, ignoring unrelated intent components ($(0, 4)$).

6. One-Hot Encoding vs. Dense Embeddings

Feature Representation One-Hot Encoding Dense Embeddings (AI)
Structure Sparse Binary Arrays $[1, 0, 0, 0]$ Continuous Floats $[0.82, -0.15, 0.40]$
Angular Property Fixed 90° Orthogonal ($\mathbf{a} \cdot \mathbf{b} = 0$) Variable Semantic Angle ($\theta < 15^\circ$)
Relationship Capture Assumes ALL categories are completely unrelated. Captures semantic match: "Laptop" $\approx$ "Computer".
Efficiency High memory footprint (sparse zeroes). Compact, highly dense information storage.

7. The "Orthogonality Trap" Visualized

Why One-Hot Fails AI Models

One-hot encoding places Laptop $[1,0]$ and Computer $[0,1]$ on perpendicular axes separated by $90^\circ$.

Laptop · Computer = 0 (Assumes Zero Overlap!)

Laptop · Banana = 0 (Same score as Computer!)

Dense Embeddings Solution: Neural networks learn dense feature representations where related concepts point in nearly identical directions ($\theta < 15^\circ$), allowing the AI model to capture true semantic similarity.

Question 11

Computer Vision: Contrast Scaling & Brightness Shift

Linear Transformations & Clipping

The Scenario: An image patch is stored as vector $\mathbf{x} = [50, 100, 150, 200]$ representing grayscale pixel values ($0 = \text{Black}, 255 = \text{White}$).

How Image Preprocessing Works:
  • Contrast ($1.5 \cdot \mathbf{x}$): Multiplies vectors to widen the gap between light and dark areas.
  • Brightness ($+ \mathbf{b}$): Adds a constant offset $[20, 20, 20, 20]$ to shift all pixels brighter.
Mathematical Step-by-Step:

$$\text{Contrast Scale: } 1.5 \times [50, 100, 150, 200] = [75, 150, 225, 300]$$

$$\text{Brightness Shift: } [75, 150, 225, 300] + [20, 20, 20, 20] = [95, 170, 245, \mathbf{320}]$$

Hardware Limit (Clipping): Displays max out at 255. Pixel 4 ($320$) is clipped down to 255 (Pure White).

ML Intuition: This exact operation models a single dense neuron layer: $\mathbf{y} = \text{ReLU}(w\cdot\mathbf{x} + \mathbf{b})$.
